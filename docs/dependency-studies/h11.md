## 2. `Connection` — every method and attribute

Constructor (`_connection.py:151-205`, signature verified live):
```python
Connection(our_role: Type[Sentinel], max_incomplete_event_size: int = 16384) -> None
```
**Anti-hallucination note:** the default `16384` comes from `DEFAULT_MAX_INCOMPLETE_EVENT_SIZE` (verified at `:167-170`) — live introspection shows `max_incomplete_event_size: int = 16384`. `our_role` must be `h11.CLIENT` or `h11.SERVER` or `ValueError` is raised (`:175-177`). httpcore always passes `our_role=h11.CLIENT` (`httpcore/_sync/http11.py:60-61`). Internal wiring set at construction (`:179-205`): `our_role`/`their_role`, `_cstate = ConnectionState()`, `_writer`/`_reader` IO pickers, `_receive_buffer = ReceiveBuffer()`, `_receive_buffer_closed = False`, `their_http_version: Optional[bytes] = None`, `_request_method = None`, `client_is_waiting_for_100_continue = False`.

Public API (all verified by live `dir` + `def` grep on `_connection.py`):
- `send(event: Event) -> bytes | None` (`:508-517`, three `@overload` variants incl. a `ConnectionClosed -> None` special case at `:504`). Serializes one event; returns bytes to write to the socket, or `None` when no output is produced. Raises `LocalProtocolError` on illegal transitions.
- `send_with_data_passthrough(event) -> List[bytes] | None` (`:544`) — `sendfile` optimization: returns a list of objects (headers bytes + user data object) instead of copying; see §6.
- `send_failed() -> None` (`:577`) — **error-recovery hook, no `receive_failed` exists in 0.16.0** (verified: `getattr(h11.Connection, 'receive_failed', None)` is `None`; the original task brief's `receive`/`receive_failed` names do NOT exist — the receive path is `receive_data` + `next_event`). Call `send_failed()` when the socket write of `send()` output fails, to roll the state machine back.
- `receive_data(data: bytes) -> None` (`:364`) — feeds raw socket bytes into the internal `ReceiveBuffer`.
- `next_event() -> Event | NEED_DATA | PAUSED` (`:438`) — parses buffered bytes into the next event; returns the `NEED_DATA` sentinel when more bytes are needed, `PAUSED` when in flow-control hold. **This is the method the brief called `receive`.**
- `start_next_cycle() -> None` (`:235`) — resets both roles `DONE → IDLE` for keep-alive reuse; raises `LocalProtocolError` otherwise. httpcore calls this (or closes) in `_response_closed`.
- `trailing_data -> Tuple[bytes, bool]` (property, `:354`) — bytes left in the buffer after the message plus a connection-closed flag (used for upgrade/CONNECT tunneling).
- `states -> Dict[role, state]` (property, `:207`), `our_state` (property, `:218`), `their_state` (property, `:225`) — introspection for debugging; values are the §4 sentinels.
- `they_are_waiting_for_100_continue -> bool` (property, `:232`) — true when the peer expects `100 Continue`.
- Private machinery worth knowing when debugging (verified `def` list): `_process_error` (`:255`), `_server_switch_event` (`:260`), `_process_event` (`:272`), `_get_io_object` (`:320`), `_respond_to_state_changes` (`:342`), `_extract_next_receive_event` (`:410`), `_clean_up_response_headers_for_sending` (`:602`, strips hop-by-hop headers httpcore must not send).

## 3. Events — `Request` / `Response` / `InformationalResponse` / `Data` / `EndOfMessage` / `ConnectionClosed` / `NEED_DATA` / `PAUSED`

Base `Event(ABC)` (`_events.py:32`, `__slots__ = ()`). All events are frozen dataclasses (`@dataclass(init=False, frozen=True)`) with `__hash__ = None` (unhashable).

### `Request` (`_events.py:41`, `__init__` `:82`)
```python
Request(*, method: bytes | str, target: bytes | str,
        headers: Headers | List[Tuple[bytes, bytes]] | List[Tuple[str, str]],
        http_version: bytes | str = b"1.1", _parsed: bool = False)
```
Fields: `method`, `target`, `headers`, `http_version` (slots, verified by `sed`). Validation performed in `__init__` (verified source): missing `Host:` on HTTP/1.1 → `LocalProtocolError("Missing mandatory Host: header")`; duplicate `Host:` → `LocalProtocolError("Found multiple Host: headers")`; illegal method/target characters → `LocalProtocolError` via `validate(method_re...)` / `validate(request_target_re...)`.

### `_ResponseBase` (`_events.py:129`, `__init__` `:137`) — shared base, not exported
Slots: `headers`, `http_version`, `reason`, `status_code`; `__post_init__` (`:168`) validates the status range per subclass.

### `InformationalResponse` (`_events.py:176`, `__post_init__` `:206`)
1xx interim responses. `status_code` must satisfy `100 <= status_code < 200` else `LocalProtocolError`. httpcore's `_receive_response_headers` explicitly accepts these (`httpcore/_sync/http11.py:181`) and keeps waiting for the final response.

### `Response` (`_events.py:218`, `__post_init__` `:247`)
Final responses. `status_code` must satisfy `200 <= status_code < 1000` else `LocalProtocolError`.

### `Data` (`_events.py:260`, `__init__` `:299`)
Message-body chunk. Fields (verified by docstring + live dump): `data` (bytes-like; with `send(..., combine=False)` any object with `len()` for sendfile), `chunk_start` / `chunk_end` markers that are **only meaningful on events emitted from `next_event`** and ignored on `send` (source docstring: "You probably shouldn't use this attribute at all").

### `EndOfMessage` (`_events.py:316`, `__init__` `:337`)
End of message; optional trailing headers (`headers` keyword, must be empty unless chunked encoding is in use).

### `ConnectionClosed` (`_events.py:358`)
`@dataclass(frozen=True)`, no fields. Signals half-close of the TCP stream in either direction.

### `NEED_DATA` (`_connection.py:51`) and `PAUSED` (`_connection.py:55`)
Singleton sentinels (`class NEED_DATA(Sentinel, metaclass=Sentinel)`). `next_event()` returns `NEED_DATA` when the buffer holds an incomplete event (bounded by `max_incomplete_event_size`, else `RemoteProtocolError`) and `PAUSED` when the reader is flow-control paused (e.g. body arrives while the local state isn't ready to consume it).

## 4. Exceptions (`h11/_util.py:12-80` — ALL THREE)

| Class | Line | Base | Meaning |
|---|---|---|---|
| `ProtocolError` | :12 | `Exception` | Base for all h11 errors |
| `LocalProtocolError` | :59 | `ProtocolError` | WE violated the protocol (bad event order, bad framing, validation) |
| `RemoteProtocolError` | :80 | `ProtocolError` | PEER violated the protocol (garbage bytes, oversize headers, bad framing) |

httpcore translates at its boundary with `map_exceptions`: `h11.LocalProtocolError → httpcore.LocalProtocolError` on send (`httpcore/_sync/http11.py:144`), `h11.RemoteProtocolError → httpcore.RemoteProtocolError` on receive (`:213`). httpx then maps those to `httpx.LocalProtocolError` / `httpx.RemoteProtocolError` (see httpcore.md §13).

## 5. The state-machine model (`h11/_state.py`)

Role sentinels (`_state.py:134-138`): `CLIENT`, `SERVER`. Per-role states (`:143-184`):
- `IDLE` (`:143`) — no exchange in progress; a `Request` (client) may be sent.
- `SEND_RESPONSE` (`:147`) — server must send a `Response`.
- `SEND_BODY` (`:151`) — body `Data`/`EndOfMessage` may flow.
- `DONE` (`:155`) — exchange complete; `start_next_cycle()` returns both sides to `IDLE` (keep-alive) — `_state.py:356`.
- `MUST_CLOSE` (`:159`) — exchange complete but connection must close (e.g. `Connection: close`, HTTP/1.0 without keep-alive).
- `CLOSED` (`:163`) — connection closed.
- `ERROR` (`:167`) — protocol error; terminal.
- `MIGHT_SWITCH_PROTOCOL` (`:172`) / `SWITCHED_PROTOCOL` (`:176`) — upgrade/CONNECT negotiation (101 Switching Protocols); internal `_SWITCH_UPGRADE` (`:180`) / `_SWITCH_CONNECT` (`:184`) proposals feed `process_client_switch_proposal` (`:271`).

`ConnectionState` (`:249`): `__init__` (`:250`), `process_error` (`:263`), `process_keep_alive_disabled` (`:267`), `process_client_switch_proposal` (`:271`), `process_event` (`:275`), `_fire_event_triggered_transitions` (`:299`), `_fire_state_triggered_transitions` (`:316`), `start_next_cycle` (`:356`).

Canonical client cycle (what httpcore drives per request): `IDLE → (send Request) → SEND_BODY → (send EndOfMessage) → DONE → (receive Response) → SEND_BODY → (receive EndOfMessage) → DONE → start_next_cycle() → IDLE`. Body framing (content-length vs chunked vs close-delimited vs HEAD/204) is chosen by `_body_framing()` (`_connection.py:93`) from method + status + headers; keep-alive eligibility by `_keep_alive()` (`:84`).

## 6. `_version` / `_connection` internals worth knowing + helper modules

- `_version.py` keeps the version in one trivial module (`__version__ = "0.16.0"`, `:23`) because setup.py execfiles it — bump tooling reads it without importing the package.
- `_connection.py:84` `_keep_alive(event)` and `:93` `_body_framing(...)` are the two pure functions that decide framing; when diagnosing a hung download, `their_http_version` + `our_state`/`their_state` tell you which framing was negotiated.
- `_receivebuffer.py:47` `ReceiveBuffer` — the internal byte accumulator (`__iadd__`, `maybe_extract_at_most`, `maybe_extract_next_line`, `is_next_line_obviously_invalid_request_line` at `:147` — the fast path that turns garbage into `RemoteProtocolError`).
- `_readers.py`: per-state readers `maybe_read_from_IDLE_client` (`:75`), `maybe_read_from_SEND_RESPONSE_server` (`:94`), `ContentLengthReader` (`:122`, `read_eof` `:136`), `ChunkedReader` (`:148`, `read_eof` `:206`).
- `_writers.py`: `write_headers` (`:22`), `write_request` (`:36`), `write_any_response` (`:44`), `BodyWriter` (`:62`) with `ContentLengthWriter` (`:84`), `ChunkedWriter` (`:101`), `Http10Writer` (`:116`).
- `_headers.py` / `_abnf.py`: header normalization/validation (`normalize_and_validate`, used by every event constructor) and the ABNF regexes (`method_re`, `request_target_re`) behind the `Illegal ... characters` errors.
- `send_with_data_passthrough` (`_connection.py:544`) exists for zero-copy `sendfile` servers — irrelevant to our client-side usage; httpcore never calls it (verified: no `send_with_data_passthrough` in `httpcore/_sync/http11.py` grep results).

## 7. How it serves us — the exact httpx → httpcore → h11 call chain

httpcore wires h11 at `HTTP11Connection.__init__` (`httpcore/_sync/http11.py:60-61`: `self._h11_state = h11.Connection(our_role=h11.CLIENT, ...)`). Per request (`handle_request`, `:65`): build `h11.Request(...)` (`:145`, inside `map_exceptions({h11.LocalProtocolError: ...})` at `:144`), `h11.Data(data=chunk)` per body chunk (`:158`), `h11.EndOfMessage()` (`:161`) — each serialized by `_send_event` (`:163`). Response side: socket bytes → `h11_state.receive_data(data)`; `h11_state.next_event()` loop in `_receive_event` (`:211-213`, inside `map_exceptions({h11.RemoteProtocolError: ...})`); `NEED_DATA` → read more; `Response` vs `InformationalResponse` (`:178-181`); `Data`/`EndOfMessage`/`PAUSED` (`:204-206`); both states `DONE` (`:241-242`) → `_response_closed` → `start_next_cycle` or close. Empty read while `their_state is SEND_RESPONSE` (`:229`) = server closed without answering → `RemoteProtocolError`.

What breaks at this layer and the exception you actually see (end-to-end through httpx):
- Our bug (send out of order, missing Host, oversize body vs framing) → `h11.LocalProtocolError` → `httpcore.LocalProtocolError` → `httpx.LocalProtocolError`.
- Server garbage / oversize headers (>100 KB httpcore cap / >16 KB h11 event cap) / early close → `h11.RemoteProtocolError` → `httpcore.RemoteProtocolError` → `httpx.RemoteProtocolError`.
- Socket-level failures (refused, reset, stalled) never reach h11 — they surface as `httpcore.ConnectError/ReadError/WriteError` and `httpx` equivalents (see httpcore.md §13). Rule of thumb: `*ProtocolError` = wire content problem (blame the bytes); `*Error` (network) = transport problem (blame the socket).

## 8. Fullest utilization — when to use this layer directly vs httpx

Honest default, stronger than for httpcore: **never touch h11 directly in app code.** It is a framing engine, not an HTTP client — no sockets, no TLS, no pooling, no timeouts. Using it means owning the socket loop, TLS upgrade, and every state transition yourself. Legitimate direct uses, all test/diagnostic:
- **M3+ protocol debugging:** replicate a failing exchange in a script with `Connection(our_role=CLIENT)`, feed captured bytes via `receive_data`, and inspect `our_state`/`their_state` + `trailing_data` to prove whether a mirror speaks valid HTTP/1.1 — faster than guessing from httpx errors.
- **Fuzz/robustness tests:** drive `next_event()` with truncated/garbage buffers to assert our error-translation (`friendly_job_error` pattern, roadmap M3) handles `RemoteProtocolError` gracefully.
- **`max_incomplete_event_size` tuning:** only if a legitimate registry sends >16 KB headers (essentially never) — and the knob lives in httpcore's constructor path, not in app code.
- Never for: downloads, API calls, proxying (all httpx/httpcore territory).

## 9. How this dependency makes our app significantly better than Termux's proot-distro

Termux's stack never sees HTTP framing at all — `curl`/shell pipelines either parse or they fail opaquely. h11 gives our app (through httpcore/httpx) protocol-level correctness guarantees Termux cannot match:
1. **Strict framing validation.** h11 rejects smuggled/invalid framing (`Transfer-Encoding` games, duplicate `Host`, illegal characters) with precise `RemoteProtocolError`s instead of silently downloading a corrupt rootfs layer. Our installer can retry a different mirror; Termux unpacks whatever bytes arrived.
2. **Correct keep-alive reuse.** The `DONE → start_next_cycle() → IDLE` cycle with `_keep_alive`/`_body_framing` negotiation reuses TLS connections across layer downloads safely — Termux's per-fetch processes pay full handshakes every time.
3. **Exact error attribution.** The Local-vs-Remote split tells us whether to fix OUR request (bad headers/auth we constructed) or distrust THE MIRROR (garbage bytes) — Termux reports both as the same dead `curl` exit code, leaving users to guess.
4. **Upgrade-path readiness.** The `MIGHT_SWITCH_PROTOCOL`/`SWITCHED_PROTOCOL` machinery (plus httpcore's `HTTP11UpgradeStream`) means CONNECT-tunnel proxying and protocol upgrades are handled statefully, not by string-matching socket bytes — the foundation under the proxy differentiators in httpcore.md §15.
The honest boundary (same as httpcore): these wins flow through httpx/httpcore into OUR code paths (M3 downloads, M4 session-adjacent fetches). Upstream proot-distro's `urllib` fetches don't benefit — which is itself an argument for routing our user-visible downloads through the httpx stack.
